# Changelog

All notable changes to noofpi are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

## [2.0.1] - 2026-11-27

### Fixed

- The `cloudflare-pages` preset no longer sends API and proxy requests to the `ASSETS` binding when the endpoint name looks like a file extension (`/_noofpi/proxy/doofpi.me.getMe`). Paths under `/_noofpi/` and the `doofpi` root are always handled by the app.
- A util in `app/utils` that is only used in a template is auto-imported (`vueTemplate: true`) instead of compiling to `_ctx.name` and being `undefined` at runtime.
- A failed first navigation (a `createError()` from a route middleware) no longer hangs the page when the client awaits the locale or devtools before mounting: the navigation is observed right away, and vue-router never settles a later `isReady()`.

## [2.0.0] - 2026-11-25

### Added

- Error overlay in `noofpi dev`. A page that fails to render on the server and has no `app/error.vue` shows a page with the error and its stack trace instead of a bare "Internal Server Error". Errors of the server render (also when `app/error.vue` handled them), uncaught errors of Vue components and event handlers, `window` errors, unhandled promise rejections and failed navigations are listed in a new **Errors** tab of the devtools, which opens by itself on a new error and counts them on the button. Production builds are unchanged.
- Devtools (`noofpi dev`) are organized in tabs: **Route** (current route, middleware chain, route rules), **Routes** (every page with its rendering, fetch mode, layout and named middleware; click a static route to navigate), **Payload** (what the server transferred to the browser for the first render: `useAsyncData` / loader data, `useState`, errors, locale, with the size of each entry), **doofpi** (the recorded requests, with a _Clear_ button) and **CSP** (violations).
- `seo` option: `noofpi build` generates `sitemap.xml` (the static pages, without params) and `robots.txt` (pointing to the sitemap) in `.output/public`. `seo.siteUrl` enables the sitemap, `seo.sitemap: false` / `seo.robots: false` disable either file, and `seo.exclude` (`routeRules`-style patterns) leaves pages out of the sitemap and disallows them in `robots.txt`. A `sitemap.xml` or `robots.txt` in `public/` is never overwritten. `robots.txt` is generated by default.
- `noofpi preview` builds, then runs the production build (`node`, `bun` and `docker` presets).
- `noofpi prepare` generates the `.noofpi/` type declarations without starting a server, for a `postinstall` script.
- `noofpi typecheck` runs `prepare`, then `vue-tsc --noEmit` (arguments after `--` go to vue-tsc).
- `--open` opens the browser once `dev`, `start` or `preview` is ready.
- `--help` / `-h` and `--version` / `-v`.
- The `node`, `bun` and `docker` presets serve precompressed files: `noofpi build` writes a `.br` and a `.gz` next to each compressible file of `.output/public` (`.html`, `.js`, `.mjs`, `.css`, `.json`, `.svg`, `.txt`, `.xml`, `.map`, `.ico`; 1 KB and up, only when smaller), and the static server answers `Accept-Encoding` with the best one the client accepts (`br`, then `gzip`), with `Vary: Accept-Encoding`.
- Static files carry `ETag`, `Last-Modified` and `Accept-Ranges`. Conditional requests (`If-None-Match`, `If-Modified-Since`) are answered with `304`, and single byte ranges (`Range`, `If-Range`) with `206`, or `416` when unsatisfiable. A range request is never served from a compressed variant.
- `build.docker.image` sets the base image of the `docker` preset's Dockerfile (default `node:22-alpine`, or `oven/bun:1` for a bun project), and `build.docker.healthcheck` the path its `HEALTHCHECK` requests (default `/`, `false` for none).
- The `cloudflare-worker` preset merges the project's `wrangler.json` / `wrangler.jsonc` (bindings, vars, routes, `compatibility_date`, extra `compatibility_flags`...) into `.output/wrangler.json`. `main` and `assets.directory` stay the build's own, `nodejs_compat` stays on, and `$schema`, `build` and `pages_build_output_dir` are not copied. A `wrangler.toml` is not read and the build warns about it.

### Changed

- The `docker` preset's Dockerfile has two stages: dependencies are installed with `npm ci --omit=dev` (`bun install --production`) in the first, and the final image only holds those, `package.json` and `.output`. It declares a `HEALTHCHECK`, and the build writes `.output/Dockerfile.dockerignore` (read by BuildKit before the project's `.dockerignore`) so the build context is only `.output` and the dependency files. Your runtime dependencies have to be in `dependencies`, not `devDependencies`.
- The `cloudflare-worker` preset pins `compatibility_date` to `2026-01-01` instead of the build date, so a build no longer picks up the runtime changes of the day it runs on. Set `compatibility_date` in your `wrangler.json` to use a newer one.
- The CLI parses its options with `node:util`'s `parseArgs`: `--port=3000` works, a missing option value or an unknown option is an error, and an invalid `--port` is rejected instead of becoming `NaN`.
- `noofpi --help` exits with code 0. An unknown command exits with code 1 and names the commands.
- **Breaking:** `tailwindcss`, `@tailwindcss/vite` and `sharp` are optional peer dependencies instead of dependencies, so projects that skip Tailwind and images no longer install them. Add `tailwindcss` and `@tailwindcss/vite` when you set `tailwind: true`, and `sharp` when you import images with `?image`. A missing package is reported with the package names to install.

### Fixed

- `noofpi/server/node` and `noofpi/server/bun` ship type declarations, and so do the `noofpi/runtime/*` subpaths (`routes`, `default-app`, `entry-client`, `entry-server`, `silent-diagnostics`) that the exports map already pointed `types` at.

## [1.2.0] - 2026-11-18

### Added

- `Register` in `noofpi/runtime` has separate `localRoutes` (`lfetch`) and `remoteRoutes` (`dfetch`, `pfetch`, `sfetch`) keys. `useDoofpi()` and `useDoofpiFetch()` type their client with the routes of its mode, taken from the `{ mode }` option or, without one, from the new `defaultFetch` key (the `doofpi.fetch` of the config). A key that is not registered falls back to `routes`.

### Changed

- `.noofpi/doofpi.d.ts` registers the `routes` export of `server/doofpi.ts` as `localRoutes` (plus `defaultFetch`) instead of `routes`, so it no longer clashes with `routes` registered in your own `env.d.ts`.
- `useDoofpi()` and `useDoofpiFetch()` are overloaded. `useDoofpi<OtherRoutes>()` and `useDoofpiFetch<T, OtherRoutes>()` keep working.

## [1.1.2] - 2026-11-18

### Fixed

- `useAsyncData`, `useDoofpiFetch` and page loaders keep the message of a doofpi API error (`DoofpiClientError`, e.g. `401 Invalid credentials`) when it happens during SSR, instead of replacing it with `Internal Server Error`. Other unexpected errors are still hidden.

## [1.1.1] - 2026-11-17

### Changed

- vue-router's console diagnostics (for example `[VUE_ROUTER_R0004] No match found for location with path ...` on an unknown URL) are silenced. `nostics`, which vue-router reports through, is aliased to a no-op module in the Vite config, and `vue-router` is bundled for SSR so the alias applies there too.

## [1.1.0] - 2026-11-17

### Added

- `noofpi dev` emulates Cloudflare bindings (vars, KV, D1, R2, ...) with Wrangler's `getPlatformProxy` for the `cloudflare-*` presets, so `env` is available in server middleware and doofpi endpoints. Needs `wrangler` installed.

## [1.0.0] - 2026-11-16

### Added

- First release: a Vue + Vite full-stack framework built around doofpi.
- File-based pages, layouts, route middleware and an error page.
- SSR or SPA, switchable globally or per route with `routeRules`.
- A built-in doofpi server (`server/doofpi.ts`) and a doofpi client with four fetch modes: `lfetch`, `pfetch`, `dfetch` and `sfetch`.
- Typed i18n, fonts and images, Tailwind CSS v4 and auto-imports.
- Security headers, CSRF checks and a request body limit by default.
- `noofpi dev`, `noofpi build` and `noofpi start`, with `node`, `bun`, `docker`, `cloudflare-worker`, `cloudflare-pages` and `github-pages` build presets.
